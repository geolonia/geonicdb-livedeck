国際標準 / NGSI-LD

データ連携のための国際標準 NGSI-LD

欧州電気通信標準化機構（ETSI）が策定した、都市・IoT のデータを表すための国際標準（ETSI GS CIM 009）です。

  • オープンな仕様 — 欧州電気通信標準化機構（ETSI）が策定・公開する国際標準。仕様書は誰でも読める
  • 統一されたデータ表現 — 「もの」を軸に、「値」「つながり」「場所」を必要な分だけ付けて表す
  • 組織を越えた相互運用性 — つながりをたどれば、別部署・別システムのデータにも届く
  • 後方互換性 — 項目や関係は後から足せる。既存の連携が読んでいる項目は変わらないので影響しない

基礎 / Multi-tenancy

マルチテナンシー: 1 つの基盤を分割してデータと権限を分離

テナントは、独立した基盤として使うことができ、データと権限を分離することが可能

自動化 / ReactiveCore Rules

条件がそろえば、あとは自動

GeonicDB 内蔵のルールエンジン。条件は CEL 式なので、気温と湿度から不快指数を算出するような複数属性の演算もそのまま書けます。外部のワークフロー基盤を別途構築せず、ブローカー内で完結。

データ連携 / Federation

組織をまたがってデータを集約

フェデレーションは、テナントやドメインの異なる複数の GeonicDB を 1 つの窓口にまとめる仕組み。手元の GeonicDB が問い合わせを別テナント・別ドメインの GeonicDB へ並列に転送し、返ってきた結果をひとつに束ねて返します。データを 1 か所にコピー・集約する必要はありません。

Context Source Registration にもとづく分散クエリ／更新の転送・結果マージ。ループ検知（Via）・警告ヘッダ（NGSILD-Warning）に対応（ETSI GS CIM 009）。

アプリ開発 / Secure by Default

セキュアなアプリケーション開発のための機能

GeonicDB は、認証情報を守る仕組みをブローカー本体と公式 SDK に寄せています。中心にあるのが DPoP（Demonstrating Proof-of-Possession / RFC 9449）— アクセストークンをそのクライアントだけが持つ秘密鍵に紐づけ、盗まれたトークンを使えなくします。

DPoP による API キーの保護 上図のとおり、トークンの文字列を盗まれても、秘密鍵がなければ API は呼べません（RFC 9449）。
アクセスコントロール API キーに origin 制限と DPoP 必須を設定。他サイトへコピーされた鍵は通りません。
XACML による認可 XACML で型・操作ごとに最小権限を割り当て。フロントに置く鍵でも被害範囲を限定できます。

※ このデッキのライブデモも、origin 制限＋ DPoP 必須の API キー 1 つで GeonicDB（ステージング）へ接続しています。

        セキュリティ詳細 / Password
        
パスワードの保護

        
パスワードそのものを守る仕組みと、パスワードを当てにいく攻撃を止める仕組みの二段構えで守ります。

        

          

            パスワードのハッシュ化
            パスワードは PBKDF2-SHA512・10 万回反復、利用者ごとのランダムソルト付きで保存。万一 DB が流出しても、総当たり解読は非現実的です。
          

          

            タイミング攻撃対策
            比較は timingSafeEqual で定数時間。存在しないアカウントでも同じハッシュ計算を挟むため、応答時間からアカウントの有無を推測できません。
          

          

            ブルートフォースアタック対策
            15 分以内に 5 回失敗でアカウントを 60 秒ロック。2 回目の失敗からは待ち時間が 2 → 4 → 8 秒と倍増し、機械的な試行が続けられません。
          

          

            パスワードスプレー対策
            1 つの IP から多数のアカウントを 1 回ずつ試す攻撃には、5 分間に 20 回失敗でその IP を 15 分ブロックして対処します。
          

          

            パスワードポリシー
            12 文字以上を必須とし、記号や大文字は強制しません（構成ルールを課さない点は NIST SP 800-63B に沿う方針）。管理者発行の一時パスワードは 7 日で失効します。
          

          

            セッションの即時失効
            パスワードの変更・リセット・管理者による上書きのたびに、その利用者の既存トークンをすべて失効。旧パスワード時代のセッションは残りません。

        用語集 / Glossary
        
用語集

        
本資料で用いた専門用語の説明

      

    


    
    

      

        

          

            A2A（Agent-to-Agent）
            AI エージェント同士が直接やり取りするための標準プロトコル。GeonicDB は Agent Card と JSON-RPC で対応。
          

          

            AES-256-GCM／AWS KMS
            AES-256-GCM は強力な共通鍵暗号方式。AWS KMS はその暗号鍵を安全に保管・管理するクラウドサービス。
          

          

            API キー
            プログラムからサービスを利用する際に使う、認証用の鍵。
          

          

            CADDE
            分野を越えてデータを安全に流通・連携させる、日本のデータ連携基盤。
          

          

            CKAN／DCAT-AP
            オープンデータを公開・検索するためのカタログの標準と代表的ソフトウェア。
          

          

            Context Broker
            さまざまなデータを共通ルールで受け取り・整え・配る「中継役」のソフトウェア。
          

          

            DoS（サービス妨害）
            大量のアクセスを集中させ、サービスを停止に追い込む攻撃。
          

          

            DPoP（RFC 9449）
            トークンの持ち主であることの証明を求め、盗まれたトークンの悪用を防ぐ仕組み。
          

          

            ETSI GS CIM 009
            NGSI-LD を定める、欧州 ETSI の国際標準仕様。
          

          

            FIWARE／FIWARE Orion-LD
            FIWARE はスマートシティ／IoT 向けのオープンソース基盤群。Orion-LD はその中核となる NGSI-LD 対応コンテキストブローカー実装。
          

          

            GeoJSON
            位置や形（点・線・面）を JSON で表す標準形式（RFC 7946）。
          

          

            Geo-query（ジオクエリー）
            「この範囲内」「近い順」など、位置情報でデータを絞り込む検索。
          

          

            JSON-LD
            意味づけ（リンクトデータ）を持たせた JSON 形式。NGSI-LD の土台。
          

          

            JWT
            改ざん検知の署名が付いた認証トークン。ログイン状態の受け渡しに使う。
          

        

      

    


    
    

      

        

          

            MCP（Model Context Protocol）
            AI（LLM）が外部のツールやデータへ安全に接続するための標準プロトコル。
          

          

            MQTT
            IoT 機器で広く使われる軽量な通信プロトコル。少ない通信量でメッセージを配信できる。
          

          

            NGSI-LD
            コンテキスト情報を相互運用可能に表現する国際標準 API（ETSI）。
          

          

            NGSIv2
            FIWARE が定めるコンテキスト API 仕様。GeonicDB は NGSI-LD と両対応。
          

          

            Nonce／Origin
            Nonce は一度きり有効な使い捨ての値（リプレイ防止）。Origin はアクセス元のドメイン。
          

          

            OAuth 2.0／OIDC
            OAuth 2.0 はアクセス権限の委譲、OIDC はそこに本人確認を加えた認証の標準。
          

          

            OpenAPI
            API の仕様を機械可読に記述するための標準フォーマット。
          

          

            PBKDF2・ハッシュ・ソルト
            パスワードを復元できない形へ変換（ハッシュ）して保存する技術。ソルトは各パスワードに加える個別の値。
          

          

            PEP（Policy Enforcement Point）
            認可の判断を実際に適用する箇所。GeonicDB は本体に内蔵するため、別途プロキシを立てる必要がない。
          

          

            PoW（Proof of Work）
            処理の前に一定量の計算を求め、機械的な大量実行を割に合わなくする仕組み。
          

          

            Property／Relationship／GeoProperty
            NGSI-LD の属性タイプ。値は Property、他エンティティへの参照は Relationship、位置は GeoProperty で表す。
          

          

            RBAC
            役割（ロール）ごとに権限をまとめて管理する方式。
          

          

            ReactiveCore Rules
            条件が満たされると自動で処理を実行する、GeonicDB のルールエンジン。
          

          

            ReDoS
            正規表現の弱点を突き、処理を極端に遅延させてサービスを止める攻撃。
          

        

      

    


    
    

      

        

          

            RTO／RPO
            障害復旧の目標値。RTO は復旧までにかかる時間、RPO は失われうるデータの時間幅。
          

          

            Scorpio
            NGSI-LD に対応する OSS コンテキストブローカーの一つ。NEC の欧州研究拠点 NEC Laboratories Europe が開発し、FIWARE の Generic Enabler に採用されている。
          

          

            Smart Data Models
            分野ごとに標準化された NGSI-LD のデータモデル集。型と属性の定義を共通化できる。
          

          

            SSRF
            サーバーをだまし、内部ネットワークやクラウド管理情報など内部資源へアクセスさせる攻撃。
          

          

            Stellio
            NGSI-LD に対応する OSS コンテキストブローカーの一つ。Easy Global Market（EGM）が開発し、FIWARE の Generic Enabler に採用されている。
          

          

            Temporal API
            データの過去の変化（時系列）を遡って取得できる API。
          

          

            WebSocket
            サーバーとブラウザが双方向にリアルタイム通信する仕組み。
          

          

            XACML
            属性に基づき「誰が何をできるか」を細かく定義する、認可ポリシーの標準。
          

          

            エンティティ（Entity）
            NGSI-LD でデータを表す単位。型と id を持ち、属性や Relationship で他のエンティティとつながる。
          

          

            オートスケール（自動スケール）
            アクセス量に応じて、処理能力を自動で増減させる仕組み。
          

          

            カスタムデータモデル
            型・属性・制約を独自に定義したデータ構造。サーバー側でバリデーションに使われる。
          

          

            監査ログ／トークン失効
            監査ログは「いつ・誰が・何をしたか」の証跡。トークン失効は漏れた認証情報を無効化する仕組み。
          

          

            空間 ID（ZFXY）
            空間を立体的なマス目に区切り、1 つの ID で位置と範囲を表す日本発の方式。
          

          

            サーバーレス
            サーバーの調達・管理をクラウド側に任せ、実際に処理された分だけ自動で確保・課金される方式。
          

        

      

    


    
    

      

        

          

            サブスクリプション（購読）
            データの作成・更新・削除を条件付きで待ち受け、変化があった時点で通知を受け取る仕組み。
          

          

            指数バックオフ
            失敗のたびに待ち時間を倍々に延ばし、連続した試行を成立しにくくする手法。
          

          

            冗長構成
            同じ機能を複数用意し、一部が壊れても止まらないようにする構成。
          

          

            スケールアップ／スケールアウト
            処理能力の増やし方。スケールアップは 1 台あたりの性能を上げ、スケールアウトは台数を増やす。
          

          

            ソフトリミット
            超えた瞬間に遮断されない上限。一時的な超過は許容され、恒常的に超える場合に契約の見直しで引き上げる。
          

          

            タイミング攻撃
            処理にかかる時間のわずかな差から、秘密情報を推測しようとする攻撃。
          

          

            テナント／マルチテナンシー
            1 つの基盤を組織・プロジェクト単位で完全に分離して共有する仕組み。データも権限も混ざらない。
          

          

            フェデレーション
            複数のブローカーを 1 つの窓口に束ね、データを移さずに横断して問い合わせる仕組み（Context Source Registration にもとづく）。
          

          

            フルマネージド
            サーバー運用・保守を提供側が引き受け、利用者は運用不要で使える形態。
          

          

            ブルートフォース／パスワードスプレー
            前者はパスワードを総当たりで試す攻撃。後者はありがちなパスワードを多数のアカウントへ広く試す攻撃。
          

          

            ベクトルタイル
            地図データを座標のまま小さなタイルに分けて配信する方式。拡大しても輪郭が滑らかで、表示を後から変えられる。
          

          

            リンクトデータ
            データ同士を参照で結びつけ、意味を保ったままつなげる考え方。NGSI-LD の核となる発想。
          

          

            レート制限（トークンバケット）
            一定時間あたりの利用回数に上限を設ける仕組み。許容量を超えると一時的に拒否する。
