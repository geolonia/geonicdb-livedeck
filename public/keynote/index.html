Beyond the API

Why AI-era data integration needs open standards — not just open data.

Hal Seki · Geolonia, Inc. FOSS4G Hiroshima 2026 · 2026-09-03
Beyond the API
Access: solved. Meaning: not yet.

We rebuilt the silos — with better licenses

Every portal has its own schema. Every API, its own field names, its own date format, its own coordinate order.

  • Open data movement: access problem solved. Credit due.
  • Each API: documented, licensed, open — and still a silo.
  • Humans pay this cost once per project. Agents pay it on every query, forever.
Pillar A · Semantics

Machine-readable ≠ machine-interpretable

Identity

Is "Chuo Community Center" the same building as "Chūō Kōminkan"?

Semantics

capacity — design capacity, or people inside right now?

Units & conventions

NGSIv2: lat, lon. NGSI-LD / GeoJSON: lon, lat. Same field, same numbers, opposite place.

Time

Measured when? Valid until? Updated by whom?

Humans absorbed these quietly for decades. Agents inherit the ambiguity — and never say "this looks strange."

Pillar A · The objection

"Won't smarter AI just figure it out?"

A smarter model does not fail less on ambiguous data. It fails better — its mistakes look more correct.

What actually happened (measured, not embellished)
  • An AI wrote a text-encoding name that doesn't exist — twice in a row ('shift-jis', then 'shiftjis').
  • A conversion script ran with no errors. Unhandled line endings silently nulled one field — in every one of 588 records. Reported as "complete."
  • "It ran" does not mean "it's right."

Pillar A · This has happened before

Smarter machines always got more structure — never less

robots.txt→ sitemaps→ schema.org→ OpenAPI→ function calling→ llms.txt→ MCP

Agents act. A misread unit no longer produces a funny reply — it produces a wrong action, and every downstream agent treats it as truth.

"Smarter agents do not need less meaning. They consume more of it, faster, with higher stakes."
Pillar B · The bet

We bet on a standard: NGSI-LD (ETSI GS CIM 009)

  • Entity — a thing with a stable ID.
  • Property — its name, its capacity.
  • Relationship — a link an agent can follow, instead of guessing.
  • GeoProperty / @context — location, time, and a shared vocabulary, built in.

Meaning lives in the data model, not in each API's documentation. That's the whole trick.

Pillar B · Why we didn't just run Orion-LD

Four requirements we couldn't compromise

  • Fully-managed, serverless. A city shouldn't run a 24/7 broker to own its data.
  • One engine, two protocols. NGSIv2 (legacy) and NGSI-LD (future), over the same data.
  • Agents as first-class users. MCP on the broker itself, from the first commit.
  • Security built in, not bolted on. One policy layer, tokens tied to the sender.

Stated as our requirements — not as criticism of the upstream projects.

Pillar B · The honest cost

What it cost, and what it bought

Cost

  • ~3,200 conformance test scenarios. 1.7 lines of test per line of product code.
  • A subset of CIM 009 v1.9.1 — not "compliant."
  • No upstream community carrying our bugs. The standard keeps moving; keeping up is now our job.

Bought

  • A service a city can adopt without running servers.
  • One engine, two protocols.
  • Agents as first-class users, not an afterthought.
  • Security without extra servers.
"We could leave the implementation because we never left the standard."

Open-sourcing GeonicDB is planned — no date, on the record.

Pillar C · What the agent gets

What a semantic layer hands an agent

  • Typed geography — location queries are native, not string parsing.
  • Validated writes — bad data fails immediately, with a clear error. It never enters the database.
  • Relationships to follow — a graph to walk, not joins to invent.
  • One MCP endpoint — the agent discovers the tools and models itself.
