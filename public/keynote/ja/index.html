柱 a · 想定される反論

「AIが賢くなれば、勝手に解決するのでは？」

賢いモデルほど、曖昧なデータでの失敗が減るわけではない。より上手く失敗する——間違いがより正しく見えるようになる。

実際に起きたこと(実測・誇張なし)
  • AIが実在しない文字エンコーディング名を書いた——二回連続で('shift-jis'、次に'shiftjis')。
  • 変換スクリプトはエラーなく完走した。だが未処理の改行コードが、588件全ての「定員」欄を静かにnullへ変えていた。「完了」と報告された。
  • 「動いた」は「正しい」を意味しない。

柱 a · これは前にも起きた

機械が賢くなるたび、構造は増えてきた——減ったことは一度もない

robots.txt→ サイトマップ→ schema.org→ OpenAPI→ function calling→ llms.txt→ MCP

AIエージェントは行動する。単位の読み違いはもう笑い話では済まない——誤った行動になり、下流の全エージェントがそれを真実として扱う。

「賢いエージェントほど、意味は要らなくなるのではない。より速く、より多くの意味を、より高い賭け金で消費するのだ。」
柱 b · 賭けた先

私たちはNGSI-LD(ETSI GS CIM 009)という標準に賭けた

  • エンティティ——安定したIDを持つ「もの」。
  • プロパティ——その名前、その定員。
  • リレーションシップ——推測ではなく、エージェントがたどれるリンク。
  • GeoProperty / @context——位置・時間・共有語彙が、標準に組み込まれている。

意味はデータモデルに宿る。各APIの説明書には宿らない。それがこの標準の要点だ。

柱 b · なぜOrion-LDをそのまま使わなかったか

譲れなかった四つの要件

  • フルマネージド・サーバーレス。自治体が自前でブローカーを24時間運用すべきではない。
  • 1エンジンで2プロトコル。NGSIv2(レガシー)とNGSI-LD(将来)を、同じデータの上で。
  • エージェントを一級市民として。ブローカー自体にMCPを、最初のコミットから。
  • セキュリティは内蔵、後付けではない。単一のポリシー層、送信者に紐づくトークン。

これは私たちの要件として述べている——上流プロジェクトへの批判ではない。

柱 b · 正直な代償

払った代償と、得たもの

代償

  • 約3,200件の適合性テストシナリオ。製品コード1行につきテスト1.7行。
  • CIM 009 v1.9.1のサブセット——「準拠」ではない。
  • 上流コミュニティが我々のバグを拾ってはくれない。標準は動き続け、追随はこちらの仕事になった。

得たもの

  • 自治体がサーバーを運用せずに導入できるサービス。
  • 1エンジン・2プロトコル。
  • 後付けでなく、最初からの一級市民としてのエージェント。
  • 追加サーバーなしのセキュリティ。
「実装は手放せた。標準を手放さなかったから。」

GeonicDBのオープンソース化は予定している——時期は明言しないが、この場で申し上げておく。

柱 c · エージェントが得るもの

意味の層がエージェントに渡すもの

  • 型付きの地理情報——位置のクエリはネイティブに動く。文字列解析ではない。
  • 検証済みの書き込み——不正なデータは即座に弾かれ、明確なエラーが返る。データベースには決して入らない。
  • たどれる関係——ジョインを発明するのではなく、グラフを歩く。
  • 単一のMCPエンドポイント——エージェントが自らツールとモデルを発見する。
